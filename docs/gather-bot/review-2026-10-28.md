## 최종 정책으로 전환하기 전에 남은 결정

- 로그·백업·문의 메일·요청 대장의 보관 기한과 파기 방법. 자동 만료는 아직 없다.
- Mac의 실제 보관 국가·암호화와 제공자 계약상 수탁자 정보, 국외 이전의 적용 근거와 필요한 고지·동의 절차.
- 책임자 법정 표시 사항·시행일·중요 변경 안내 기간. 공개된 Discord 사용자명을 법정 표시의 충족 근거로 단정하지 않는다.
- 요청 대장의 실제 보관·접근 통제와 삭제 요청을 VM·Mac 복사본 모두에 반영하는 검증.
- 메일 수신·회신과 Discord DM 접근성. 검토를 이유로 임의의 메일·DM을 발송하지 않았다.
- 실제 이용자 10명의 모집·티어·대타·탈퇴·재가입·삭제 체험. 자동 테스트나 사전점검을 이 체험으로 대체하지 않는다.

30일·180일 DB 보관안은 이번 검토에서도 채택하지 않았다. 기존 운영 자료를 임의로
삭제하거나, 개인정보 권리 포기·면책·제재·자동 참가 평가 같은 새로운 정책을 추가하지 않았다.
최종 고지 요건이 남은 상태에서 Portal의 처리방침·약관 URL을 최종 정책으로 바꾸지 않는다.

## OWKR Docs 이전

공개 정책 원본과 검토 기록을 owkr-docs로 이전했다. 참가자/Balance 안내는 별도 처리 범위로 유지하며 봇 정책은 초안이다. 테마의 브라우저 로컬 저장과 화면 스크립트를 안내에 반영했다. 봇 저장소는 기존 공개 주소의 이동 안내만 배포한다.

## 모집 미완료 자동 취소·공지 삭제 취소

선택한 취소 시각 전까지 최초 정원 완료가 없는 내전만 취소하며, 모집 원본 공지 삭제도 해당 내전 취소로 연결한다. 원본 DB 정리와 Discord 정리 재시도를 분리하여 최소 메시지 작업 기록만 완료 시까지 보관한다. 실패가 지속되면 보관이 길어질 수 있고, 전송 직후 기록 전 중단 시 중복 안내 가능성을 고지했다. 법적 고지 미완료 항목과 초안 상태는 유지한다.

## 이용약관 1.0 확정

운영자가 2026-10-28 당일 시행을 선택했다. 이용약관의 초안·미정 표시를 제거하고 서비스 범위·무료 제공·책임 경계·모집 및 취소·이용 중단·이의 제기·변경 안내·서비스 종료 절차를 명시했다. 일반 변경은 7일, 불리하거나 중대한 변경은 30일 사전 안내하며 소급 적용·묵시적 동의 간주·포괄 면책·전속 관할 강제는 두지 않았다.

Discord 개발자 약관 §3(b), §5 및 약관법 제3조의 취지를 참고했다. 이 문서 확정을 법률 적합성 보증, 이용자별 고지·동의 완료, 개인정보처리방침 확정 또는 정식 운영 전환으로 표시하지 않는다. 서비스 종료의 실제 파기 절차는 그때 운영 DB·로그·백업·문의 자료별로 실행하고 확인해야 한다.

## 2026-10-29 · 화면 정리와 개인정보처리방침 재검토

- 보관 기한·국내 Mac/FileVault·문의 수신 경로·담당 공개 표기는 운영자가 확인했다. 봇 PR #18로 VM 로그 날짜별 정리와 VM/Mac 7일 백업 정리를 구현·적용했다. 위의 초기 검토 목록에서 해당 항목은 해결된 것으로 읽는다.
- 현재 개인정보처리방침 0.4는 이 운영 기준과 일치한다. 이용약관 1.0.1의 시행일·이용 조건은 바꾸지 않는다.
- 개인정보 보호법 제28조의8의 현재 조문을 다시 확인했다. 공개된 리전·보관 기한만으로 운영 계정에 적용되는 제공자 계약·이전 근거·법정 고지 완료를 증명할 수 없다. 계약 자료와 최종 고지 확인 전에는 개인정보처리방침을 확정하지 않는다.
- 화면의 확정본·시행 중 배지는 제거한다. 미확인 개인정보처리방침의 초안 본문·noindex와 과거 공개 원문은 보존한다. 장식 배지 제거를 정책 시행으로 해석하지 않는다.
- FAQ 도우미는 정적 문서 선택형 안내이며 외부 AI로 질문을 보내지 않는다. 봇 참가·대기·취소·삭제·운영 시간은 현재 제품 정책과 대조했다.

## 2026-10-29 · 삭제 요청·백업 복원 격리 검증

- [봇 PR #19](https://github.com/Overwatch-KR/owkr-gather-bot/pull/19)에서 실제 저장소·티어 삭제 확인 콜백·백업 생성·7일 만료 정리를 가상 데이터로 연결했다. 삭제 후 백업 복원, 삭제 전 VM/Mac 복사본을 본뜬 두 폴더에서 요청 재반영·재시작·지연 저장 차단, 다른 사용자·타 길드·참가 상태·경고 보존을 확인했다. 전체 Python 테스트 206개와 compileall·pip check가 통과했다.
- 삭제 전 백업에는 원문이 남으며 요청 자동 재반영은 없다. 실제 서비스 메서드로 복원 DB에 요청을 재반영한 뒤 수집 차단을 확인했다. 무검토 복원·시작을 허용한 검증이 아니다.
- 운영 DB·Discord 메시지·메일·요청 대장·VM/Mac 기존 백업은 읽거나 변경하지 않았다. Oracle 작업 보류와 실제 모든 운영 복사본 대조·요청 접수 전체 검증은 그대로 남는다. 디스크의 물리적 복구 불가능성을 확인한 것으로 해석하지 않는다.
- 공개 정책의 처리 범위·본문·시행 상태는 변경하지 않는다.
