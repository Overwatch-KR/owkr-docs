## Discord 공개 안내와 제출 준비

Discord 개발자 약관 제5조가 요구하는 수집 정보·사용/공유·보관·삭제 요청 안내를
현재 동작에 맞춰 제공한다. 비영리 목적도 이 안내를 생략하는 이유가 되지 않는다.

- [x] 무료 커뮤니티 봇의 목적, 운영자와 실제 문의 경로 설명
- [x] 수집 항목·이용 목적·보이는 범위·호스팅/메일 처리 경로 설명
- [x] 내전·경고·로그·백업·문의·요청 대장의 보관/삭제 기준 설명
- [x] `/개인정보`의 삭제 범위와 이메일/DM 추가 요청 경로 설명
- [x] 실제 이용 조건·문의 안내·최초 발행일·갱신일·이전 문구 제공
- [ ] Developer Portal의 실제 검증 체크리스트 및 정책·약관·지원 URL 등록 상태 확인

공개 주소는 `https://overwatch-kr.github.io/owkr-docs/gather-bot`이다.
공개 웹 접근과 내용 검사는 배포 후 확인하고, Portal에 등록할 때도 현재 URL과 실제
처리가 일치하는지 확인한다. 문서 게시만으로 Discord 검증 승인이나 법률 적합성 인증을
받았다고 표시하지 않는다.

**Oracle 공식 회신·유료 계정 전환·기업용 계약 심사를 Discord의 필수 제출 요건으로
추가하지 않는다.** 10명 실사용 시험도 앱 검증의 공식 필수 절차로 표시하지 않는다.
단일 길드 파일럿의 기능 시험과 대규모 공개 배포를 위한 Discord App Verification은 구분한다.

## 법적 검토의 범위

친목 도모 단체 운영에는 법 제58조제3항의 일부 적용 제외 가능성이 있지만,
비영리·개인 운영이라는 이유만으로 모든 의무가 면제된다고 단정하지 않는다.
특히 국외 이전은 이 예외만으로 해결되지 않는다. 법 제26조·제28조의8 등 실제 적용
여부와 필요한 조치는 운영 점검 항목으로 구분하고, Discord 제출 체크리스트와 섞지 않는다.

사용자는 이번 변경에서 공개 안내를 커뮤니티 운영 범위로 조정하도록 요청했다.
개인정보 원본의 `status: draft`와 noindex는 미해결 적용 검토를 완료로 바꾸지 않기 위해
유지한다. 공개 본문에는 과도한 계약 검토 메모 대신 현재 처리 사실과 이용자 권리를 설명한다.
실명·개인 전화번호를 임의 공개하거나 존재하지 않는 담당 부서를 만들어 넣지 않는다.

[계약·국외 처리 상세 검토](contract-transfer-review-2026-10-29.md)는 참고 기록이다.
이 기록의 제공자 문의안은 전송하지 않았고 새 계약에도 동의하지 않았다.
미확인 계약 버전·지원 접근 국가·Gmail 처리 범위를 확인 완료로 표시하지 않는다.

## 운영 검증과 추가 확인

로그 최대 30일·백업 생성 후 7일·문의 종료 후 90일·최소 요청 기록 종료 후 1년을
운영자가 승인했다. VM 로그·VM/Mac 백업은 자동 정리하고 메일·대장은 매일 확인한다.
내전 시작·취소 후 DB 정리와 서버 재적 중 경고 보관은 이 일수 기준과 구분한다.

VM/Mac 파일 권한·Mac FileVault·문의 수신 경로를 확인했고, VM 백업 13개·Mac 백업 5개의
임시 복원·무결성 검사와 실제 운영 이미지의 가상 삭제·재수집 차단 시험이 통과했다.
실제 요청은 0건이었다. 개별 요청의 본인 확인·모든 복사본 처리·회신을 완료한 것으로
확대하지 않는다. 10명 Discord 실사용 시험은 운영자 요청으로 보류했다.

[운영 대조 기록](review-2026-10-28.md)과 봇 저장소의 삭제 요청·복원 검증 기록에
확인한 범위와 남은 항목을 보존한다. 새 데이터·복사본·처리 경로가 생기면 다시 대조한다.

## 변경 이력과 발행 기준

모든 문서의 최초 발행일 `publishedAt`은 2026-10-27로 유지한다. 이용약관의 기존
시행일 2026-10-28과 문의 접수 안내의 최초 적용일은 바꾸지 않는다. 갱신일과 버전은
실제 변경 때 갱신하고 공개 이전 본문·당시 상태는 `src/content/policy-revisions`에
불변 GitHub 소스 URL과 문서별 고유 순서로 보존한다.

`/gather-bot/changes`는 주요 공개 문구를 비교한다. 과거 내용을 새 기준에 맞춰
고쳐 쓰지 않는다. 내부 검토 기록은 웹 빌드에 포함하지 않으며 비밀 설정·DB·백업은
Git이나 정적 사이트에 포함하지 않는다. 구현 단위 커밋을 보존해 병합하고
`pnpm check`와 공개 페이지·변경 비교를 확인한다.
