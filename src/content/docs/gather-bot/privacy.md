시간을달리는소녀는 OWKR Discord 커뮤니티의 내전 모집과 참가 안내를 돕는 무료 봇입니다.
qtaghdi가 비영리 목적의 커뮤니티 운영을 위해 개인 운영합니다. 이 안내는 봇 이용 중
어떤 정보를 사용하고, 언제 정리하며, 삭제를 어떻게 요청할 수 있는지 설명합니다.

## 운영자와 문의처

- 봇 운영·개인정보 문의 담당: **qtaghdi · 내전 총관리자**
- 이메일: [qtaghdi@gmail.com](mailto:qtaghdi@gmail.com)
- Discord: `qtaghdi`에게 비공개 메시지

문의와 내 정보의 확인·수정·삭제·처리정지 요청을 위 경로로 받습니다.
개인정보가 포함된 내용은 공개 채널이나 공개 GitHub 이슈에 올리지 마세요.
서버 전체의 운영 및 참가자·팀 밸런스 서비스의 정보 처리는 각 안내에서 별도로 다룹니다.

## 사용하는 정보와 목적

봇은 내전 참가 순서, 참가자·대기자, 티어 작성 상태와 시작 전 안내를 처리하고
중단 후에도 같은 내전을 복구하기 위해 다음 정보를 사용합니다.

| 정보 | 사용 목적 |
| --- | --- |
| Discord 사용자 ID·표시 이름, 참가·취소 시각과 반응 순서 | 참가자·대기자 구분과 중복 처리 방지 |
| 관리자 ID, 서버·채널·메시지 ID와 내전 일정 | 내전 공지 연결, 운영 및 알림 복구 |
| 티어 안내에 답장한 메시지 원문·메시지 ID·작성 및 수정 시각 | 해당 내전의 티어 제출 연결과 최신 작성 상태 확인 |
| 대기실 음성 채널 입장 사용자 ID | 시작 전 대기실 미입장 참가자 확인 |
| 내전별 티어 수집 중단 기록 | 본인 삭제 요청 후 현재 내전에서 다시 수집하지 않도록 처리 |
| 경고 대상·종류·기록 관리자·관련 시각·요청 ID·취소 기록 | 관리자가 결정한 노쇼·비매너 경고 관리와 중복 기록 방지 |
| 알림 처리 상태·오류·운영 로그 | 장애 조사와 재시도·중복 알림 방지 |
| 문의자의 이메일 주소·Discord ID·요청 내용·처리 결과 | 문의 답변과 본인 확인, 개인정보 요청 처리 |

새 티어 제출은 해당 내전의 티어 안내에 답장해야 연결됩니다. 이미 연결된 메시지의
수정·삭제도 처리하며, 재시작 시 필요한 채널 이력을 조회해 누락된 제출을 보완합니다.
티어 메시지에는 게임 운영에 필요한 내용만 작성해 주세요.

음성을 녹음하거나 음성 채널에 연결하지 않습니다. Discord 연결 과정에서 메시지·멤버·
음성 상태 등이 일시적으로 메모리에 남을 수 있지만 이 전체를 봇 DB에 저장하지는 않습니다.
로그에는 사용자·메시지 식별자와 오류가 포함될 수 있으며 토큰·환경 변수 전체·티어 원문을
기록하지 않도록 관리합니다.

## 정보가 보이는 범위와 보관 위치

참가 반응과 직접 작성한 메시지는 해당 Discord 채널 권한에 따라 다른 사람에게 보일 수
있습니다. 봇도 내전 공지와 필요한 참가 안내·멘션을 보냅니다. 광고·정보 판매·AI 학습
목적으로 정보를 사용하지 않으며 외부 매치 서비스나 AI 모델에 티어 정보를 자동 전송하지 않습니다.

| 경로 | 위치와 용도 |
| --- | --- |
| 봇 DB·운영 로그 | Oracle Cloud Infrastructure 일본 도쿄 VM에서 내전 운영·복구에 사용 |
| 서버 내부 백업 | 같은 VM에서 매일 한국 시간 오전 6시에 DB·설정·공지 문구 백업. 토큰 제외 |
| 외부 백업 복사본 | 한국에 있는 운영자의 Mac에 수동 복사. FileVault와 접근 제한 폴더 사용 |
| 문의 메일 | 개인 Gmail 계정에서 접수·답변. 봇 DB와 별도로 처리 |
| 공개 안내 웹 | GitHub Pages에 정책·문의 문서 게시. 운영 DB·설정·백업은 게시하지 않음 |

도쿄는 봇 DB와 서버 백업의 저장 위치입니다. Oracle은 서비스 지원·사고 대응·복구를 위한
해외 접근을 계약에서 설명하며, Google도 여러 국가의 서버를 이용합니다. 문의 메일이나
제공자 자체 계정·시스템 정보의 처리는 위 VM 저장 위치와 구분됩니다.
[Oracle 개인정보 처리 계약](https://www.oracle.com/contracts/docs/data-processing-agreement-oracle-services-081425.pdf),
[Google 개인정보처리방침](https://policies.google.com/privacy?hl=ko),
[GitHub 개인정보 안내](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement)에서 각 제공자의 처리 설명을 확인할 수 있습니다.

해외 처리에 관한 문의나 처리정지·삭제 요청도 운영자에게 보낼 수 있습니다.
현재 봇은 위 호스팅과 Discord 연결을 사용하므로 처리 범위에 따라 봇을 통한 참가·티어
처리가 제한될 수 있습니다. 운영자는 요청 범위와 가능한 조치를 확인해 답변합니다.
이 안내의 게시나 일반 참가 반응을 국외 이전에 관한 별도 동의로 취급하지 않습니다.

## 보관 기간과 정리

| 자료 | 보관·정리 기준 |
| --- | --- |
| 내전·참가·반응·티어·연결·알림·수집 중단 기록 | 운영 중 보관하고 내전 시작·취소 후 정리. 봇 실행 중 약 10초 간격으로 확인하며, 중단 중 남은 기록은 다음 가동 시 정리 |
| 취소 공지 정리·재시도 기록 | 서버·채널·공지 ID와 안내 처리 상태 등 최소 정보만 정리 작업 완료까지 보관. 참가 명단·티어 원문은 복제하지 않음 |
| 경고와 경고 취소 이력 | 서버 재적 중 보관. 탈퇴 확인 시 삭제하고 재가입 전 기록도 정리. 봇 실행 중 약 1시간 간격 및 경고 조회·변경 전 확인 |
| 봇 운영·VM 접속 로그 | 최대 30일. 날짜·용량 기준으로 자동 정리하며 용량 제한으로 먼저 삭제될 수 있음 |
| 서버·Mac 백업 | 생성 후 7일 기준으로 매시간 정리. Mac이 꺼지거나 잠든 동안에는 다음 가동 시 확인 |
| 문의 이메일·첨부 자료 | 문의 처리 종료 후 90일 이내 파기. 운영자가 매일 확인 |
| 최소 요청 처리 기록 | 처리 종료 후 1년 이내 파기. 복원 시 삭제 요청을 반영하는 데 필요한 최소 기록을 접근 제한 대장으로 관리 |

봇 운영 시간은 한국 시간 **월요일부터 목요일은 오후 8시부터 다음 날 오전 2시까지,
금요일부터 일요일은 24시간**입니다. 일요일에서 이어지는 월요일 새벽도 오전 2시까지
운영합니다. 비운영 시간에는 봇의 데이터 정리·재적 조회도 중지되며 다음 가동 시 확인합니다.

권한·통신 오류나 백업 생성 기록 오류가 있으면 완료로 처리하지 않고 재시도·점검합니다.
위 기간은 운영자가 관리하는 자료의 기준이며, 제공자 자체 계정·시스템 정보는 각 제공자의
정책에 따릅니다. DB 행 삭제가 디스크의 물리적 복구 불가능성까지 보장하는 것은 아닙니다.

## 내 정보의 확인·수정·삭제

서버의 `/개인정보`에서 본인에게만 보이는 안내와 티어 삭제 확인 버튼을 제공합니다.
확인하면 **봇 DB의 본인 티어 원문과 메시지 연결을 삭제하고, 현재 참가 중인 내전에서는
다시 수집하지 않습니다.** 참가·대기 상태는 유지되며 내전 시작·취소 후 정리됩니다.

다른 정보의 확인·수정·삭제·처리정지나 경고에 관한 요청은 이메일 또는 Discord DM으로
문의해 주세요. 경고 정정·취소·삭제는 관리자가 판단해 처리합니다. 별도의 자동 제재는 없습니다.
비밀번호·인증 토큰·신분증 사본을 요구하지 않으며, 타인 자료를 처리하지 않도록 필요한
최소 범위에서 본인을 확인합니다. [문의·삭제 요청 안내](/owkr-docs/gather-bot/support)
에서 접수 절차를 확인할 수 있습니다.

봇의 티어 삭제 버튼이나 참가 취소만으로 Discord 원문·경고·로그·기존 백업까지
모두 삭제되지는 않습니다. 추가 요청이 있으면 해당 자료와 서버·Mac 복사본을 확인하고,
완료한 범위와 남은 처리·보관 범위를 구분해 알려드립니다. 이전 백업을 복원할 때는
봇을 다시 연결하기 전에 삭제·수집 중단 요청을 반영합니다.

## 보호와 안내 변경

운영 DB·설정·백업은 접근을 제한하고, 전용 서버 접속 키·관리 IP 제한·파일 권한과
읽기 전용 컨테이너를 사용합니다. Mac 복사본은 FileVault를 사용합니다.
사고가 확인되면 운영자가 영향을 확인하고 필요한 이용자 안내와 후속 조치를 진행합니다.

서비스를 종료하면 불필요한 DB·로그·백업·문의 자료를 확인해 정리합니다.
처리 내용이나 보관 기준을 바꾸면 변경 내용·적용일을 이 문서와 필요한 서버 공지에
안내하고, 별도 동의나 통지가 필요한 경우 해당 절차를 따릅니다.
이전 문구는 [문서 변경 이력](/owkr-docs/gather-bot/changes#privacy)에서 확인할 수 있습니다.
