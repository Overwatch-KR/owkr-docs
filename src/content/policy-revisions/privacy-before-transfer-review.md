## 처리 목적과 정보

시간을달리는소녀는 Discord 내전 모집, 참가·대기자 관리, 티어 제출 연결,
시작 전 대기실 안내와 재시작 복구를 지원합니다.

| 정보 | 목적 |
| --- | --- |
| Discord 사용자 ID·표시 이름 | 참가·대기 구분, 티어 제출 연결 |
| 참가·취소 시각, 반응 순서와 처리 결과 | 참가 순서·중복 처리, 복구 |
| 관리자 ID, 서버·채널·메시지 ID, 내전 일정 | 내전 운영, 메시지 연결·알림 |
| 티어 메시지 원문·메시지 ID·관련 시각 | 최신 제출 저장과 작성 상태 확인 |
| 대기실 음성 채널 입장 사용자 ID | 미입장 참가자 확인 |

| 내전별 티어 수집 중단 정보 | 본인 삭제 요청 후 재시작·이력 조회를 통한 재수집 차단 |
| 문의자의 이메일 주소·Discord ID·요청 내용·처리 결과 | 문의 답변과 본인 확인, 열람·수정·삭제·처리정지 요청 처리 |

티어 정보는 지정 서버·채널에서 참가자와 제출 시각 등의 조건에 따라 저장합니다.
새 제출은 해당 내전 안내에 답장해야 저장합니다. 답장 없는 새 메시지는 연결하지
않습니다. 과거 DB에 이미 연결된 메시지는 수정·삭제를 계속 처리하며, 재시작 시
채널 이력을 조회하여 답장 제출과 기존 연결 메시지의 활동을 보완합니다.
음성을 녹음하거나 음성 채널에 연결하지 않습니다. Discord 라이브러리는 수신한 메시지와
서버·멤버·음성 상태 등을 실행 중 메모리에 캐시할 수 있으며, 이 캐시 전체를 봇 DB에
저장하지는 않습니다. 로그에는 토큰·환경 변수 전체·티어 원문을 기록하지 않도록
설계되어 있으나 사용자·메시지 식별자와 오류가 포함될 수 있습니다.

## 공개 범위와 처리 위치

참가 반응과 직접 작성한 메시지는 Discord 채널 권한에 따라 다른 이용자에게
보일 수 있습니다. 봇은 해당 채널에 참가 안내와 대상 멘션을 전송합니다.
Discord의 공개 메시지와 봇 DB의 저장 정보는 서로 다릅니다.

현재 외부 매치 서비스나 AI 모델로 티어 정보를 자동 전송하지 않습니다.
2026-10-28에 확인한 처리 환경은 다음과 같습니다.

| 구분 | 처리 환경과 범위 |
| --- | --- |
| 봇 DB·운영 로그 | Oracle Cloud Infrastructure의 일본 도쿄 리전 VM과 영구 부트 디스크 |
| VM 내부 백업 | 같은 VM에서 매일 한국 시간 오전 6시에 DB·설정·공지 문구를 백업. 토큰 제외 |
| VM 외부 복사본 | 한국에 있는 운영 담당자의 Mac. FileVault 암호화·접근 제한 폴더를 사용하며 외부 복사는 수동, 7일 만료 정리는 자동 |
| 서버 관리 | 운영 담당자의 전용 SSH 키와 승인한 관리 접속 IP 사용. 봇의 서버 관리자 역할과 VM 관리 권한은 별개 |
| 공개 안내 웹 | GitHub Pages. 정책·문의 안내만 게시하며 DB·설정·백업은 배포하지 않음 |
| 문의 이메일 | Google Gmail의 qtaghdi@gmail.com. 발신 주소와 요청 본문을 처리하며 봇 DB와 별개 |

Mac의 한국 보관·FileVault 사용과 이메일·Discord DM 수신 가능 여부는 운영 담당자가 확인했습니다. 제공자와 체결한 계약상 수탁자 정보 및 문의 이메일 처리 위치는 최종 확인 대상입니다. 일본 리전 보관 사실을 국내 보관으로
표현하지 않습니다. 국외 이전의 적용 근거·이전 항목·받는 자·시점과 방법·보유 기간·
연락처·거부 방법 등의 고지를 확인하고, 필요한 동의·안내 절차를 별도로 갖춰야 합니다.
단순한 서버 생성이나 이 초안 공개가 그 절차를 대신하지 않습니다.

공개 웹에는 별도 접수 폼·광고·분석 스크립트·외부 폰트를 넣지 않습니다. GitHub 등
제공자가 접속 IP 등 서비스 운영 정보를 처리할 수 있는 사항은 제공자의 정책과
구분합니다. 봇 운영자가 공개 웹 방문자 정보를 별도 DB로 수집하지는 않습니다.
OWKR Docs는 화면 테마 선택을 브라우저 로컬 저장소(`owkr-theme`)에 저장하고,
목차·FAQ 도우미 등 화면 동작을 위한 스크립트를 사용합니다. FAQ 도우미는 사이트에
포함된 문서를 보여주며 질문을 외부 AI 모델로 전송하지 않습니다.

## 보관과 파기

내전 DB 기록은 복구에 필요한 운영 중에 보관합니다. 봇 실행 중에는 내전 시작·취소 후 약 10초
간격으로 세션과 참가·반응·티어·연결·알림·수집 중단 기록을 정리합니다. 중단 중
정리되지 못한 기록은 재시작 때 정리합니다. 오류 시 완료로 간주하지 않고 재시도합니다.

자동 취소와 모집 공지 삭제 취소의 Discord 정리를 재시도하기 위해, 별도 작업 기록에 내전 식별자,
서버·채널·모집/티어/대타 메시지 ID, 시작 시각·대기실 이름·안내 전송 여부만 보관합니다.
참가자 명단·티어 원문은 이 작업 기록에 복제하지 않습니다. 종료된 내전 원본 정리와 별개로
메시지 정리·안내가 완료될 때까지 유지하고 완료 후 삭제합니다. 권한·통신 오류가 계속되면
작업도 남을 수 있으므로 운영 담당자가 오류를 확인하고 처리해야 합니다.

경고와 취소 이력은 서버 재적 중 기간 만료 없이 보관합니다. 경고가 있는 사용자만
봇 실행 중 정기적으로(약 1시간 간격) 재적을 조회하며 탈퇴를 확인하면 삭제합니다. 경고 조회·변경
전에도 확인하고 재가입 시각 이전의 경고는 정리합니다. 권한·통신 오류는 탈퇴로
간주하지 않습니다. 즉시 탈퇴 감지 방식이 아니므로 삭제에 지연이 있을 수 있습니다.

운영 시간은 한국 시간 월~목 20:00~다음 날 02:00, 금~일 24시간입니다. 일요일에서
월요일 새벽 02:00까지 이어집니다. 비운영 시간에는 개인정보 정리와 재적 조회도
중지되므로 위 간격이 전체 경과 시간을 뜻하지는 않습니다. 다음 가동 시 정리합니다.

보관 기간과 파기 기준은 다음과 같습니다.

| 자료 | 보관 기준과 정리 |
| --- | --- |
| 봇 운영·VM 접속 로그 | 최대 30일. 날짜·용량 기준으로 자동 회전·정리하며 용량 제한으로 먼저 삭제될 수 있음 |
| VM·Mac 백업 | 생성 후 7일. 매시간 만료를 확인하고 정리. Mac이 꺼지거나 잠든 동안에는 다음 가동 때 확인 |
| 문의 이메일·첨부 자료 | 문의 처리 종료 후 90일 이내 파기. 운영 담당자가 매일 만료 여부 확인 |
| 최소 요청 처리 기록 | 처리 종료 후 1년 이내 파기. 접수·처리 범위와 결과, 복원 시 삭제 반영에 필요한 최소 항목만 접근 제한 대장에 보관 |

내전 DB 정리는 Discord 원문·기존 로그·백업·문의 메일까지 자동 삭제하지 않습니다.
백업 정리에서 잘못된 생성 기록·링크 등 오류가 발견되면 삭제를 멈추고 담당자가
확인합니다. 복사 실패로 남은 미완성 백업도 담당자가 확인해 같은 보관 기준으로
정리합니다. 정리 작업 중단·실패는 다음 가동 시 재시도하고 수동 점검합니다.
DB 행 삭제만으로 디스크의 잔여 데이터까지 복원 불가능하게 제거됐다고 안내하지 않습니다.

Discord 메시지 삭제는 전체 개인정보 삭제와 다릅니다. 시작 전 조건에 맞는 삭제
이벤트로 최신 티어 원문이 제거될 수 있지만 연결·참가·백업 전체가 지워지지는
않습니다. 시작 후에는 삭제 이벤트를 자동 처리하지 않지만 내전 DB 정리 대상이 됩니다.

## 수정·삭제 요청

서버에서 `/개인정보`를 실행하면 보관·문의 안내를 본인에게만 확인할 수 있습니다.
확인 버튼으로 본인 티어 원문과 연결 기록을 지우고 현재 참가한 내전의 티어 재수집을
중단할 수 있습니다. 참가·대기 상태는 유지되고 시작·취소 후 정리됩니다. 경고는
관리자에게 비공개로 수정·삭제를 요청하며 관리자는 `/경고`에서 취소·전체삭제합니다.

이 버튼은 Discord 원문·경고·기존 로그·백업을 지우지 않습니다. 전체 개인정보
삭제 완료로 안내하지 않습니다. 추가 요청은 위 이메일로 접수합니다. 본인 확인·완료
안내·백업 처리의 세부 절차는 [요청 안내](/owkr-docs/gather-bot/support)에 기록했습니다. 완료한 범위와
확인하지 못한 범위를 구분해서 답변합니다.

진행 중·시작 후·취소 후 요청 모두 처리 위치를 확인하고, 백업을 복원할 때는 보관 중인 삭제·처리정지 요청을 먼저 반영하여 재수집을 막습니다.

## 보호 조치와 변경 안내

단일 프로세스·SQLite 운영, 멘션 대상 제한과 관리자 명령 검사를 사용합니다.
VM의 전용 접속 키·관리 IP 제한, 설정 파일 600·데이터 및 백업 폴더 700 권한,
일반 사용자로 실행되는 읽기 전용 컨테이너와 백업 복사본 무결성을 확인했습니다.
부트 볼륨 전송 암호화는 사용합니다. Mac은 운영 담당자가 FileVault 사용을 확인했습니다. 이 확인을 완전한 디스크 파기나 모든 사고 대응의 검증으로 확대하지 않습니다. 사고 접수와 대응 담당은
qtaghdi이며, 필요한 이용자·제공자·관계 기관 통지의 범위와 절차를 확인합니다.

공개 전 시행일과 중요 변경의 안내 경로를 확정합니다. 한국 개인정보보호법 등
적용 법령의 필수 기재 사항·이용자 권리·미성년자 관련 의무는 실제 운영 형태에
따라 별도 검토합니다.
